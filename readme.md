# Task Timer — что изменилось

## 1. Win+C / SIGTERM теперь завершает процесс сразу

Раньше `signal.signal(...)` обрабатывался, только когда интерпретатор Python
случайно "просыпался" (например, на тике таймера анимации), поэтому Win+C
иногда как будто не срабатывал, и нужно было жать Ctrl+C прямо в терминале.

Теперь используется классический для Qt+Python приём — `signal.set_wakeup_fd`
+ `QSocketNotifier`: при получении SIGTERM/SIGINT ОС гарантированно и сразу
пишет байт в специальный сокет, который сразу же будит цикл событий Qt, не
дожидаясь никаких таймеров. Плюс добавлена страховка: если сохранение записи
или закрытие вдруг зависнет, процесс всё равно принудительно завершится через
1.5 секунды (`os._exit(0)`), так что второй Ctrl+C больше не понадобится.

## 2. Развёрнутое окно теперь можно тянуть за края

В свёрнутом виде ("таблетка") размер по-прежнему фиксирован. В развёрнутом —
у окна появились зоны захвата по краям и углам (6px), потянув за которые можно
менять размер. Минимальный размер и размер по умолчанию задаются в конфиге
(`window.full_min_width/height`, `window.full_width/height`).
Изменённый размер сохраняется только в рамках сессии — при следующем запуске
окно снова стартует с размера по умолчанию из конфига.

## 3. Все цвета и уровни прозрачности вынесены в конфиг

Файл: `~/.config/task-timer/style.json`

Он создаётся автоматически при первом запуске со значениями по умолчанию.
Структура:

```json
{
  "colors": { "window_grad_start": "#10101a", "accent_idle_start": "#6d28d9", ... },
  "opacity": { "input_bg_alpha": 35, "blob_alpha": 135, ... },
  "difficulty_labels": ["Лёгкая", "Средняя", "Сложная", "Эпик"],
  "difficulty_color_keys": ["difficulty_easy", "difficulty_medium", "difficulty_hard", "difficulty_epic"],
  "tag_palette": ["#f87171", "#fb923c", ...],
  "animation": { "theme_transition_ms": 450, "blob_speed_scale": 1.0 },
  "window": { "full_width": 320, "full_height": 440, ... }
}
```

Так как файл лежит в `~/.config`, к нему можно спокойно писать из других
твоих скриптов — например, единым скриптом-темизатором менять `colors.*`
сразу везде, где ты его подключишь.

**Пока приложение запущено**, оно следит за этим файлом (`QFileSystemWatcher`)
и при любом изменении на диске плавно (за `animation.theme_transition_ms`
миллисекунд, ease-out) переезжает от старых цветов/прозрачностей к новым —
никакого мигания или дёрганья. Работает даже если редактор пересохраняет файл
через "удалить и создать заново" (rename-on-save).

Что НЕ анимируется намеренно:
- цвета уже сохранённых записей истории (цвет сложности фиксируется в
  момент сохранения записи, как и раньше);
- цвета уже созданных тегов (см. ниже, они статичны по дизайну).

## 4. Вкладка "Теги" + теги у записей

Появилась третья вкладка (иконка 🏷) — создание и удаление тегов.
На вкладке "История" у каждой записи есть кнопка **🏷+**, которая открывает
меню с чекбоксами всех тегов — можно отметить нужные, они сразу сохраняются
и отображаются цветными плашками под записью.

**Цвет тега не выбирается вручную и не меняется:**
- Каждому новому тегу присваивается цвет по его порядковому номеру из
  `tag_palette` в конфиге (тег №0 → `tag_palette[0]`, тег №1 → `tag_palette[1]`
  и т.д.) — значит, можно централизованно настроить палитру тегов в конфиге.
- Если тегов создано больше, чем цветов в палитре, цвет для "лишних" тегов
  генерируется автоматически по методу золотого угла (137.508°) — соседние
  тона гарантированно не похожи друг на друга, даже если тегов сотни.
- Цвет "запекается" в `~/.local/share/task-timer/tags.json` при создании тега
  и дальше не пересчитывается, даже если ты поменяешь `tag_palette` в
  конфиге — так что уже созданные теги не будут "прыгать" по цвету.

Данные тегов и истории (`history.json`, `tags.json`) остались в
`~/.local/share/task-timer/`, отдельно от конфига интерфейса — так конфиг
можно свободно шарить/шаблонизировать между скриптами, не боясь задеть данные.
